# Пайплайн Claude (оркестратор) → Codex (worker)

Дата: 2026-10-05. Статус: утверждён в диалоге, ждёт ревью пользователя.

## Цель

По явной команде пользователя выполнять план разработки так: Claude Code на Sonnet 5.5 планирует, оркестрирует и проверяет, Codex (gpt-6.1-sol, reasoning high) пишет код и тесты. Без явной команды Claude Code и Codex работают раздельно.

## Принятые решения

| Вопрос | Решение |
|---|---|
| Автономия | Подтверждение пользователя после каждой задачи (гейт на задачу) |
| Где пишет Codex | Отдельный git worktree на запуск, ветка `codex/<slug>` |
| Транспорт | Плагин `codex@openai-codex` v1.0.6, `codex-companion.mjs task` (подход A) |
| Активация | Только явный вызов `/codex-pipeline`; иначе работа раздельная |
| Git | Все git-записи делает только Claude; Codex git не пишет |

`codex mcp-server` удалён в Codex CLI 0.154.0, поэтому MCP не используется.

## Не цели

- Автономный режим без гейтов, параллельное выполнение задач, push и merge.
- Собственный MCP-сервер, обёртка над `codex exec`, subagent-форвардер.
- Файл состояния запуска.
- Отдельная команда `/pipeline`: skill сам вызывается как `/codex-pipeline`.

## Артефакты

| Путь | Назначение |
|---|---|
| `.claude/skills/codex-pipeline/SKILL.md` | Цикл оркестрации; frontmatter `disable-model-invocation: true` |
| `.claude/skills/codex-pipeline/references/task-brief.md` | Шаблон брифа для Codex |
| `.claude/skills/codex-pipeline/scripts/worktree.sh` | `create <slug> [base-ref]`, `path <slug>` и `remove <slug>` |
| `CLAUDE.md` (корень) | Правило: Codex только по явной команде пользователя, `codex:codex-rescue` сам не вызывать |

## Роли

**Claude (Sonnet 5.5)** не правит продуктовый код. Планирует, пишет брифы, запускает Codex, проверяет результат, общается с пользователем и делает все git-записи. Если сессия идёт не на Sonnet 5.5, skill предупреждает об этом перед стартом, но модель не переключает.

**Codex (gpt-6.1-sol, high)** пишет код и тесты по TDD внутри worktree. Модель и effort закрепляются флагами `--model gpt-6.1-sol --effort high`, а не только конфигом `~/.codex/config.toml`.

## Активация

- Запуск: `/codex-pipeline <путь к утверждённому плану | описание задачи>`.
- Путь к плану: цикл стартует сразу. Описание: сначала `brainstorming` и `writing-plans` с их гейтами.
- Без вызова пайплайн не участвует в работе: нет общих файлов состояния, хуков и фоновых процессов. Review gate плагина остаётся выключенным.
- Утечка, которую закрывает `CLAUDE.md`: у плагина есть субагент `codex-rescue` с описанием «Proactively use…», через который Claude мог бы сам делегировать Codex. Правило мягкое (инструкция, не запрет); `permissions.deny` не используется, чтобы не ломать ручной `/codex:rescue`.

## Подготовка запуска

1. Предполётная проверка: `codex-companion.mjs setup --json`. Если Codex не готов или нет логина, запуск прерывается до создания worktree.
2. `worktree.sh create <slug> [base-ref]` создаёт ветку `codex/<slug>` от `base-ref` (по умолчанию `HEAD` текущей ветки) и симлинки `venv` и `frontend/node_modules` из основного дерева. Codex читает по ним, но писать не может.
3. Незакоммиченные правки основного дерева в worktree не попадают. Если план опирается на них, skill останавливается и просит закоммитить их или указать другую базу.

## Цикл на каждую задачу плана

1. **Бриф.** Claude по шаблону `task-brief.md` пишет самодостаточный бриф: цель, файлы в scope, вне scope, шаги TDD, критерии приёмки, команды проверки. В бриф входит явная фраза «разрешено изменять файлы в этом worktree» (AGENTS.md иначе велит Codex писать код в чате) и запрет git-записи.
2. **Запуск.** `codex-companion.mjs task --cwd <worktree> --write --model gpt-6.1-sol --effort high --json --prompt-file <brief>`; долгие задачи с `--background`.
3. **Сбор.** `status` и `result` для фоновых задач, stdout для обычных.
4. **Проверка (Claude).** Дифф сверяется со scope; файл вне scope означает отклонение. Тесты Claude запускает сам; дифф читается против критериев приёмки.
5. **Автоисправление.** Если проверка не прошла, замечания уходят в тот же поток через `--resume-last`. Максимум 2 раунда, затем эскалация к пользователю.
6. **Гейт.** Пользователю показываются дифф, вывод тестов и вердикт Claude. Ответ: принять, вернуть с заметками или остановить. Без ответа коммита нет.
7. **Коммит.** После принятия Claude коммитит в worktree с префиксом `task N:`.
8. **Завершение.** После последней задачи вызывается `finishing-a-development-branch`; удаление worktree только по команде пользователя.

## Механика плагина (проверено по исходникам 1.0.6)

- `--write` включает sandbox `workspace-write`, без него `read-only`.
- `task` принимает `--cwd`, `--prompt-file`, `--json`, `--model`, `--effort`, `--background`, `--resume-last`, `--fresh`.
- Корень workspace = `git rev-parse --show-toplevel` от cwd, поэтому у worktree собственный реестр job'ов и собственная область `--resume-last`.
- Git-директория linked worktree лежит вне его корня, поэтому Codex, вероятно, не сможет делать `git add` и `git commit`; это причина того, что git пишет только Claude.
- Внимание: `task --help` не выводит справку, а запускает реальный job с промптом «--help». Справка доступна только через `codex-companion.mjs --help`.

## Границы безопасности

- Запись Codex только внутри worktree; основное дерево недоступно.
- Всегда запрещено в брифе (инварианты `backend/AGENTS.md`): секреты и `.env`, `static/`, `media/`, CSV/XLSX, `celerybeat-schedule`, `manage.py migrate`. Миграции только через `makemigrations`.
- Установка зависимостей невозможна; при упоре в зависимость Codex останавливается и просит решения.
- Нет push, нет merge в `main`, нет удаления worktree без команды пользователя.

## Обработка ошибок

| Ситуация | Действие |
|---|---|
| Codex не готов или нет логина | Прервать до создания worktree |
| Job упал, отменён или пустой дифф | Один повтор с нуля, затем эскалация |
| Codex вернул вопрос вместо кода | Claude отвечает из плана, иначе спрашивает пользователя |
| Проверка не прошла | До 2 раундов `--resume-last`, затем показать как есть |
| Нет PostgreSQL, Redis или Docker для тестов | Гейт помечает «не проверено: …»; автопринять нельзя |
| Фоновый job без прогресса | Предложить отмену, не ждать бесконечно |
| Прерванный запуск | Прогресс читается из коммитов `codex/<slug>` с префиксом `task N:` и из плана; продолжение с первой задачи без коммита |

## Проверка пайплайна

1. **`worktree.sh`:** тест на одноразовом git-репозитории во временной папке: создание ветки `codex/<slug>`, симлинки, отказ при отсутствии базы, идемпотентное удаление; основное дерево не затрагивается.
2. **Смоке-прогон на реальном репозитории:** одна безобидная задача (добавить тест для чистой функции); проверяется сквозной путь бриф → `task` с закреплёнными модель и effort → проверка → гейт → коммит.
3. **Проба границ:** задача, просящая записать файл вне worktree, должна провалиться; задача, создающая файл вне scope, должна быть отклонена Claude.
4. **Проба opt-in:** у skill стоит `disable-model-invocation: true`; в обычной сессии без `/codex-pipeline` `codex-companion.mjs status --all` не показывает новых job'ов.

## Критерии приёмки

- После прогона `git status` основного дерева совпадает со снимком «до».
- Результат лежит только в коммитах ветки `codex/<slug>` в worktree.
- Гейт блокирует: без ответа пользователя коммита нет.
- Без явного вызова Claude и Codex не взаимодействуют.

## Результаты проверки

Дата: 2026-10-05. Плагин `codex@openai-codex` 1.0.6, Codex CLI 0.160.0, модель `gpt-6.1-sol`, effort `high`.

**Проба sandbox** (отдельный worktree, `task --write`):

| Действие Codex | Результат |
|---|---|
| Запись в основное дерево (`/Users/artem/Desktop/avito/.probe-outside.txt`) | заблокирована: `operation not permitted` |
| Запись внутри worktree | прошла |
| `git add` и `git commit` в worktree | заблокированы: `Unable to create '…/avito/.git/worktrees/<slug>/index.lock': Operation not permitted` |
| Запись через симлинки `frontend/node_modules` и `venv` | заблокирована |

Основное дерево после пробы совпало со снимком «до». Подтверждено решение «git пишет только Claude».

**Смоке-прогон `/codex-pipeline`** (план `docs/superpowers/plans/2026-10-05-codex-pipeline-smoke.md`, 2 задачи):
- Предполётная проверка, снимок, создание worktree `codex/codex-pipeline-smoke`, бриф, запуск `task` с закреплёнными моделью и effort, проверка, гейт и коммит отработали по SKILL.md. Шаг 6 (завершение, `finishing-a-development-branch`) в смоке не выполнялся.
- Коммиты `task 1` и `task 2` появились только после ответа пользователя «принять». Случай, когда ответа нет, не проверялся.
- Проба scope. Сначала Codex отказался создавать файл вне scope, сославшись на бриф. Затем оркестратор вручную повторил запрос в тот же поток с формулировкой «приоритетнее scope» (такого действия SKILL не предусматривает, это часть пробы; в смоке-плане такого текста нет), и Codex файл `SCOPE_PROBE.txt` создал. Проверка 5.4 отклонила результат, автоисправление (раунд 1 из 2) через `--resume-last` убрало файл. В коммиты `SCOPE_PROBE.txt` не попал. Ограничение: нарушение спровоцировал сам оркестратор, поэтому проба подтверждает механику 5.4 и 5.5, а не независимое обнаружение нарушения.
- Критерии приёмки: `git status` основного дерева совпал со снимком, `htmlText.ts` не менялся, результат только в двух коммитах ветки `codex/codex-pipeline-smoke`, реестр job'ов основного workspace не изменился (все 4 job'а прошли в реестре worktree).
- Opt-in: попытка вызвать skill как модель дала `Unknown skill: codex-pipeline` (согласуется с `disable-model-invocation: true`, но то же сообщение даёт и ещё не загруженный skill, поэтому это не прямое доказательство); вызов пользователем `/codex-pipeline <план>` сработал после `/reload-skills`. Первая попытка пользователя до этого не оставила следов в репозитории и не дошла до сессии; причина не установлена (возможно, skill, созданный в середине сессии, не был подхвачен сразу).

**Находки, требующие решения пользователя:**
1. Codex не может запустить Vitest в worktree: Vite пишет временный конфиг в `frontend/node_modules/.vite-temp`, а `node_modules` в worktree симлинк только для чтения (`EPERM`). Оба раза Codex честно сообщил «не проверено» и ничего не обходил; тесты запускал Claude. Из-за этого Codex не может сам выполнить шаг «падающий тест → проходящий тест» на frontend.
2. `touchedFiles` в ответе `task --json` не включает файлы, созданные командами оболочки; для проверки scope надёжен только `git status` в worktree (так и написано в SKILL.md).
3. Усиленная формулировка, добавленная оркестратором в повторном запросе («приоритетнее scope»), заставила Codex нарушить scope из брифа. Защитой остаётся проверка Claude на шаге 5.4, а не послушность Codex.

- Проверено 2026-10-05 (см. «Результаты проверки»): sandbox `workspace-write` запрещает `git add`, `git commit` и запись по симлинкам; допущение подтверждено, дизайн не меняется. Открыт новый вопрос про Vitest в worktree (находка 1).
- Привязка к внутреннему CLI плагина версии 1.0.6 (CHANGELOG содержит только 1.0.0): при обновлении плагина прогнать смоке-прогон заново.
- Нужны ли тесты Django (PostgreSQL, Redis) в worktree и как их запускать, определяется на этапе плана.
